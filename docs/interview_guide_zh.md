# GamePulse 面试讲稿

## 30 秒版本

GamePulse 是一个跨平台游戏 Voice-of-Player Agent Skill。用户只需要输入游戏名，系统会解析中英文别名，自动发现 Steam、Reddit、YouTube 和 B站等来源，抓取真实评论，统一数据结构并生成带原始证据链接的问题优先级报告。对微博、小红书、抖音等权限更严格的平台，它只使用获批接口、授权会话或合规导出，并明确报告缺失来源。

## 2 分钟版本

这个项目第一版使用模拟行为数据，虽然能展示 SQL 和分析流程，但我发现它缺少真实使用价值，所以把核心重构成了实际的数据采集和跨平台分析系统。

现在入口是游戏名，而不是 app ID 或视频 ID。系统先利用公开元数据解析别名，例如英文名对应的中文名，再为不同平台生成搜索词。Steam 连接器会自动解析 app ID 并分页抓评论；B站连接器会搜索相关视频并抓公开评论；Reddit 使用 OAuth，YouTube 使用官方 Data API。微博、小红书、抖音由于通用搜索和评论权限更严格，系统采用获批接口或授权导入，并且不会绕过登录、验证码或限流。

所有来源都被统一成同一个 schema，保留来源、内容 ID、发布时间、抓取时间、原始链接、推荐状态、互动量等字段。增量运行会按稳定 ID 去重，同时为每次运行保存 manifest，明确哪些平台抓到了、哪些平台因为缺权限没有抓到。

当前仓库里的真实样例是《Tower of Fantasy》：300 条 Steam 评论和 27 条以“幻塔”为关键词获得的 B站评论。报告识别出账号迁移/数据丢失是高度负向问题，同时保留原评论链接。评分只用于安排调查顺序，不把公开评论直接解释成留存或营收影响。

## 面试官可能追问

### 为什么不能所有平台都直接爬？

因为平台的公开接口、登录要求和数据授权不同。一个真实可用的产品不应该把绕过风控当作核心能力。我的设计把来源分成公开接口、官方凭据接口和授权导入三类，并在 manifest 中报告实际覆盖率。

### 为什么只做关键词分类？

这是可审计的 baseline，适合验证采集、schema 和产品逻辑。仓库同时暴露了 `Other` 占比，用它衡量 taxonomy 是否不足。下一版可以建立人工标注集，比较多标签分类模型或 LLM 的准确率、成本和稳定性。

### 如何避免把热搜或高赞当成真实玩家比例？

搜索结果、点赞量和评论量只表示被观察样本中的可见度。我按平台分别报告，并使用跨来源一致性来安排调查优先级；真正的影响判断仍需结合一方行为数据或实验。

### 如果继续开发？

我会接入已获批的中文平台数据服务，增加定时快照、主题漂移监控、人工标注评估集，以及与游戏一方留存和客服工单的隐私安全关联。
